# worker/

The GPU-side half of DNA-Entropy-Graph: a Python package (`dna_entropy`) that reads a
sequence (GenBank/FASTA/pasted), runs it through a genomic language model (Evo 2, or a
deterministic mock for tests), computes per-position Shannon entropy, and exports it as
tracks for IGV/GenBank-aware editors/genome browsers. It ships in two ways:

- `dna-entropy` — the human-facing science CLI (`src/dna_entropy/cli.py`), for running
  the pipeline by hand on a laptop or GPU box.
- `dna-entropy-worker` — the container entrypoint (`src/dna_entropy/worker/cli.py`),
  invoked by `vm/startup.sh` on a per-job cloud VM: reads `manifest.json`, runs the
  pipeline once per input, writes `status.json`/`progress.jsonl`/`result.json`
  (`docs/job_contract.md`).

This README is intentionally short. The real documentation lives in the repo-root
`docs/` tree, not here:

- **`docs/science_and_formats.md`** — the science itself: entropy definition, windowing,
  bidirectional (forward/reverse-complement) prediction, output file formats.
- **`docs/job_contract.md`** — the manifest/status/result JSON contract between this
  package and the C# app; `docs/contract/*.json` (generated by
  `scripts/gen_manifest_schema.py`) is its machine-checked schema.
- **`docs/onboarding.md`** — how to get `pytest worker/tests -m "not gpu"` green on a
  fresh checkout.
- **`docs/architecture.md`**, **`docs/tech_stack.md`** — where this package fits in the
  larger app + cloud + worker system.

## Dev commands

From the repo root, in `worker/.venv`:

```powershell
worker\.venv\Scripts\python.exe -m pytest worker/tests -m "not gpu" -q   # laptop: no GPU/Evo needed
worker\.venv\Scripts\python.exe -m pytest worker/tests -q                # GPU box: full suite
uvx ruff check .                                                          # from worker/
uvx ruff format --check .                                                 # from worker/
```

`worker/tests/gpu`-marked tests need a real CUDA stack and the `evo` extra
(`pip install -e ".[evo]"`); they are skipped automatically without one.

## Attribution

This package is not a from-scratch rewrite. Its `src/dna_entropy/` tree — readers,
validation, predictors, analysis, annotators, writers, pipeline, CLI, and the matching
`tests/` — was ported byte-for-byte from a prior proof-of-concept repository,
**`DNA-Entropy-Genbank`** (private, local checkout at the time of migration; commit
`8026bf5c4afbe3021c1f7e79a17a93af4eaad84b`), minus its `cloud/` (gcloud/SSH orchestration)
and PyInstaller packaging modules — those are gutted from the shipped package because the
approved DNA-Entropy-Graph design talks to Google APIs directly from C#
(`docs/superpowers/specs/2026-09-18-appendix-b-cloud-design.md`), never `gcloud`/SSH from
Python. See `docs/migration/2026-09-19-worker-migration-inventory.md` for the full
file-by-file KEEP/ADAPT/GUT breakdown.

Two directories under `worker/legacy/` preserve pieces of that lineage as historical
reference only (nothing in `worker/legacy/` is imported or shipped by this package):

- **`worker/legacy/cloud/`** — `DNA-Entropy-Genbank`'s own `cloud/` package (gcloud
  wrappers, the always-on GPU keeper, zone/offer escalation), kept for its error
  classification, quota-parsing, and health-check logic, which informed the C#
  `DnaEntropyGraph.Cloud` design.
- **`worker/legacy/dna-entropy-v1/`** — two files (`orchestrator.py`, `cli.py`) from an
  even older prototype, **`dna-entropy`**
  (`https://github.com/Raaif-Yousuf/dna-entropy`, commit
  `c0f2375314a7d96be89c84d775c99110579a0582`), kept purely for its per-job,
  create-then-delete-by-default VM lifecycle (with a `--keep` flag) — a design
  `DNA-Entropy-Genbank` itself later replaced with an always-on keeper, but which the
  approved DNA-Entropy-Graph design brings back (one VM per job, Stop by default, Delete
  option, Keep-alive option).

`worker/README.legacy.md`, `worker/CLAUDE.legacy.md`, `worker/LICENSE.prototype`, and
`worker/docs-legacy/DESIGN.md` are `DNA-Entropy-Genbank`'s own unmodified docs, kept as
reference for the same reason — see each file's own heading and
`docs/migration/2026-09-19-worker-migration-inventory.md` for what superseded them.
