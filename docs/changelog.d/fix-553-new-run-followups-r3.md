- fix(app): New run follow-ups from the #63 review (#553). Stacked on #103 (it changes the same view model). (1) A cancelled add no longer marks as stopped a check that Treat as RNA started on the same file: `ValidateAsync` now says whether a check was applied, superseded, cancelled or never started, and only a check that never started ends the pill's checking state (`InputPillItem.AbandonIfNeverChecked`, which does nothing once any check has begun). (2) A run that cannot start now says one action by what failed: a file that cannot be found or opened, a Google Cloud or sign-in failure, or anything else (a plain disk or history-store IO failure is not the user's file) (`NewRunStatusStartFailedFile` / `Cloud` / `Other` in Resources.resw), and logs its error class through the existing `IDiagnosticsLog` (source `new-run`, no job id, the exception type name plus the cloud error kind for a cloud failure, such as `CloudOperationException:Quota`; never a message or file name; the line is posted first and a log that throws cannot hide it), which `FileDiagnosticsLog` writes to `logs\app.log` for the diagnostics zip. The old `NewRunStatusStartFailed` key is now the Cloud line. (3) The start-failed and file-chooser-failed lines go through `PostStatus`, so they no longer wipe a line another add has already said. User guide: new section in 07-when-something-goes-wrong.md.
