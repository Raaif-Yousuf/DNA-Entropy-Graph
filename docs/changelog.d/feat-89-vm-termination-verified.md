- Cloud (#89): a VM's `maxRunDuration` is the user's cap plus 15 minutes, and the worker now really enforces that cap itself (`limits.maxRunSeconds` was parsed and never read): past it the worker stops between records, uploads what finished and writes `result.json` with `RUN_TIME_LIMIT`, recorded as `run_time_limit`. A VM Compute Engine deleted at its limit with no result is also recorded `run_time_limit`, not "lost".
- Worker (#89 review): the run cap now counts from VM start (`/proc/uptime`), not from the worker start, so boot and pull come out of the cap; and a run whose last window finished in time is not failed because its upload crossed the cap.
