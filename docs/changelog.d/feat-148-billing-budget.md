- Settings has a Budget alert group (issues #148, #222): one button creates, changes or removes a Google Cloud Billing budget that emails the billing administrators at 50%, 90% and 100% of a monthly amount (default 50), found by an installation-id display name so two users on one billing account never share one. The group shows the thresholds the budget really has; a budget that follows last month's spend leaves the amount box empty (so Save cannot turn it into a fixed 50) and a missing or removed budget puts the default back in an empty box; typed text is never overwritten and the box is not replaced on the first open. A missing billing role shows one sentence, a link to the console budgets page and a copyable request for the billing administrator; a refusal to switch the Budget API on, or to read whether it is on, names a project owner instead (the read refusal stops the save before any budget call and offers a copyable request for the Service Usage Viewer role). The list wording ("50%, 90% and 100%") comes from Resources.resw. New `IBudgetGateway`, `BudgetService`, `GoogleBudgetGateway` (`Google.Apis.CloudBillingBudget.v1`) and a FakeGcp budget part. Create or update and Remove are possible only after the last read of the budget state succeeded for the shown project: a failed look (no connection, no access, a refused read of the API state) turns both off and the status names the one action (open Settings again, a billing administrator, or a project owner with a copy request), so an existing budget is never overwritten or deleted blind. A refused read of the API state on a look or a remove is reported like Save's (project owner, Service Usage Viewer), the copy confirmation names the recipient of the request copied, and a box the user cleared stays cleared.
