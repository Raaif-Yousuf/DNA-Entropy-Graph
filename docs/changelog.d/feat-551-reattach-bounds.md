- A reattach waits at most the mutation timeout plus a 30 s margin (5 min 30 s by default, on the reconciler's clock) for a user cancel of the same run to settle, so one cancel that never ends no longer holds back every run's outcome until the app shuts down; and the action a reattach reports is derived from the phase the row ended as (a run cancelled during the Failed write is reported as the cancel, not as FailedUnrecoverable); a cancel that was cut short or whose end was not recorded is reported as `CancelInterrupted`, never as a finished cancel (#551).
