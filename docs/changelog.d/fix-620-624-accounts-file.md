- Two copies of the app changing the saved account list at once no longer lose a change: a sign-in in one and a project choice in the other both persist (every change is applied to the file as it is under the lock; same account and field, the later writer wins) (#620).
- When the saved account list is held open by another program at launch, the setup page now says so with a Try again button instead of looking signed out, and the account appears once the file can be read (#624).
- A failed save after a damaged account list was set aside no longer loses the notice, a sign-in clears a pending notice instead of refusing the next project choice, an expiry mark or a sign-out no longer overrides or deletes a fresh sign-in of the same account from another copy, and a damaged list the folder will not let the app move aside always says the folder is the problem (#620, #624).
- Signing out (or marking a dead sign-in) now checks, under the account-list lock, that the saved token is still the one it found, so a sign-in of the same account from another copy of the app is never signed out, deleted or revoked (#620).
- Account-list changes stay consistent with the saved sign-in when two copies of the app run: a sign-in saves its token under the same lock as its list entry, a failed token-file delete still refreshes the account display, and a dead sign-in still says "sign in again" (#620, #624).
