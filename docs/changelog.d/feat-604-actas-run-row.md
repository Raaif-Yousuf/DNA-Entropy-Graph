- A run refused for the worker account's actAs permission, or by the worker-identity step (default account missing, access not applied), is now recorded under its own code (`permission_actas`, `worker_default_account_missing`, `worker_identity_not_applied`) instead of the generic `permission`. The Runs page shows that message and, for `permission_actas`, a "Copy request for the project owner" button that copies a request naming `roles/iam.serviceAccountUser` on the worker account's email. `ProvisionResult.FailureCode` and `RunErrorCodes.For(CloudError, kind)` carry the code. The request names the account the VM was asked to run as (the default Compute Engine account when an organization policy refused the worker account, read from a `[vm-account=...]` mark on the failed row) and the signed-in account as the grantee.
