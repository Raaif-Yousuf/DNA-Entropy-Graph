- The billing step is real in the code (issues #51 and #539): the app reads whether your project has billing, links the one open billing account you have, asks which one when you have several, and when you have none gives a Link billing button that opens Google's billing page for your project. A project that already has an account linked while billing is off is never re-linked or replaced without asking: with other accounts to pick it asks which one, with none it says Fix billing account (opens Google's billing page for the project), and a link Google accepted that left billing off says so (BILLING_STILL_OFF, action Pick another billing account). If you may use a billing account but not link projects to it, it offers Copy request for the billing admin (BILLING_NO_PERMISSION). The wizard page that shows it arrives with #99, and production still uses the fake cloud until #56, so nothing in the shipped UI changes yet. Adds Google.Apis.Cloudbilling.v1 (Apache-2.0).
- Google's refusals are classified by what they mean (issues #51 and #539): a permission denial that mentions billing (for example a missing billing role), Google's standard "you may not use this project to pass quota" refusal and a project-side permission denial are permission problems (ask the project owner), never "billing is off", "you reached a limit" or a request for the billing admin; a refusal that is really an organization block or an "already exists" keeps that meaning even when its text says "does not have permission"; a Billing service that is off and a billing quota limit are named as such; and "Billing is required for this project" is read as billing off.
