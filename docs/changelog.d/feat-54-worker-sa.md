- The worker identity is real in the code (issue #54): `GoogleIamGateway` creates (or adopts) the service account `dna-entropy-worker`, creates (or undeletes, or repairs) the custom role `dnaEntropyWorker` with exactly the four Compute permissions the VM needs, binds it at the project with a version-3 IAM condition that only matches VMs named `deg-*`, and binds `roles/storage.objectAdmin` on the results bucket only, never touching a binding it did not add and writing nothing on a second run. When an organization policy forbids service accounts it falls back to the default Compute Engine account with the same bindings and a yellow note (`WORKER_DEFAULT_ACCOUNT`). A refusal to act as the account is `PERMISSION_ACTAS` with the action Copy request for the project owner. Production still uses `FakeGcp` until #56.
