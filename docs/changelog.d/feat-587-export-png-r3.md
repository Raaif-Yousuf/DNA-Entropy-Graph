- app: Save picture on the Results page (#587, stacked on #552). The PNG of the entropy overview is now named `<record>.entropy.png` (was `.entropy.overview.png`), is saved in the run's own results folder as before (never next to the input), and carries a title naming the run and the record, "Position (bases)" along the bottom and "Entropy (bits, 0 to 2)" up the side, drawn on the fixed 0 to 2 scale. `IOverviewImageExporter.Export` takes an `OverviewImageLabels` (title and axis text, from `Resources.resw`) so the chart library stays out of Presentation. A picture is never written over a file already there: if `<record>.entropy.png` exists (another run in a shared folder, or two records whose names clean up alike) the new one is `<record>.entropy (2).png`, then `(3)`. A failed save still says to check the results folder and choose Save picture again. Unproven on a real build: see `docs/ToTest.md`.
  Fix round: only a run brought in from the earlier version (its folder is the user's own) sends its pictures to a separate exports folder; a cloud-downloaded run's picture goes in its own results folder. The exports folder is one per run (`<run> exports`), made only when a picture is written and removed again if the save fails, so a second picture is numbered `(2)` beside the first. One helper, `RunOutputFolders.UniqueFilePath`, picks the name and counts a folder of that name as taken; any exception from the exporter becomes the save-failed message; a missing exports root says so with its own message (`Results_ExportPngNoFolder`) instead of blaming the results folder.
