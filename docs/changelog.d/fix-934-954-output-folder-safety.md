- Every run output folder the app creates now holds a `.dna-entropy-run` marker naming its job (#934), cloud runs included (`RunTransfer` passes the job id to `CreateUnique`, and a failed run's marker-only folder is still removed). Delete files on this PC requires the marker: a folder of another run, or with an unreadable, linked or oversized marker, is refused (Open folder button); a folder with no marker (an older run, or one named by a damaged history row) is deleted only after one question showing its full path, unless it is the user's own shell folder (profile, Documents, Desktop, Pictures, Music, Videos, Downloads itself) or sits directly inside one, which is refused with no question. The link and marker state is re-checked immediately before the first file is deleted, so a swap between the plan and the delete stops it. A refusal shown without a dialog (or whose dialog could not be shown) is a toast that names the row's Open button. A run saved straight to a drive (`D:\`) says why Delete and Download again are not offered, and the output-folder check refuses a whole drive (#954).
