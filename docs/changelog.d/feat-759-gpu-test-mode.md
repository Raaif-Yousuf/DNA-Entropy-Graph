- GPU tests can now run end to end on a labelled VM (#759, #83): `CloudCli vm create` accepts `--worker-image` (digest-pinned), `--bucket`, `--startup-mode gpu-test` and `--expect-gpu` and attaches the startup metadata through `StartupMetadata.Build`; new `bucket ensure` and `object get` verbs; `worker/vm/startup.sh` has a gpu-test mode (`gpu_test_run`) that runs `pytest -m gpu` in the image, uploads `logs/gpu-test.log` and then `logs/gpu-test-result.json`, treats skipped or zero tests as exit 6, and applies the lifecycle; `Dockerfile.cuda` carries pytest and the tests; `scripts/cloud_gpu_test.ps1 -Apply -Image <digest>` polls the result, pulls the log and passes only when pytest exited 0. Proven by stub-CloudCli self-test, CloudCli tests over `FakeGcp`, and bash tests of `gpu_test_run`; not run on a real VM.
- gpu-test mode hardening after cold review (#759): the container runs under `--init` with a name, `timeout -k 30` and a `docker kill` on timeout (a hung test is actually stopped and `timedOut:true` is recorded); the deadline is counted from boot; early failures (GPU not visible, pull failed) write the result object so the script stops waiting; `cloud_gpu_test.ps1` refuses a reused `-JobId` and distrusts a result from another image or VM; tests are chosen by `-m gpu` collection, not by grepping file text; `CloudCli object get` over 4 MiB exits 0 with a truncation notice; `vm create --worker-image` prints a warning that the digest is not checked against the pinned list.
