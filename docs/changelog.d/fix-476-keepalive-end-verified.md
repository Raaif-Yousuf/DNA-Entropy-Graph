- A Keep-alive VM that is still running after its window plus a 5 minute grace is now stopped or deleted by the app while it is open (#476, Hard Rule 11): a 5 minute sweep finds it by the run's job-id label (never a VM a later run has reused), ends it per the run's "after the window" choice, and the finished run gets the note `keepalive_ended_by_app` unless it already has a note. The run itself no longer holds anything while the window runs. Tested on FakeGcp. Each row is swept in its own project and as its own account, the end is fenced with a fingerprinted `ending-since` label so a VM another run reuses is never ended, the end call is cut off before that mark expires (a second sweep inside the window gets only what is left of it, and starts no end call with under two minutes left), a fence write an organization policy refuses is logged as `org_policy` (the VM is then not ended without the fence), a row with no finish time is skipped and logged, a row whose VM is settled is not looked up again, the sweep ends nothing when the laptop clock disagrees with the platform clock (or the platform sends no time at all: one log line per process, `maxRunDuration` stays the backstop), and it notes only a VM it found running.
