- Fixed a race in the test double `FakeGcp` (#875, #910): a stop, start, poll or queued grant was a read-then-write of the VM row, so a delete landing between them was overwritten and the deleted VM came back (this made `A_delete_asked_while_a_stop_is_in_flight_is_sent_and_the_row_names_the_delete` and `A_resumed_run_waits_out_a_request_still_queued_past_the_boot_timeout_and_makes_no_second_create` fail once in CI). Every change to an existing FakeGcp VM row (stop, start/reuse, relabel, boot, stopping and preempt polls, the queued-to-granted swap) now goes through one compare-and-swap helper, `UpdateVm`, that gives up when the row was deleted; a stop is never dropped by a state change except a preempt that Compute took first; a delete clears the VM's scheduled preemption; the simulated worker's deferred end and the max-run expiry act only on the VM incarnation they were made for; a queued request is replaced by the granted VM in one step, so a poll never sees it missing. A guard test fails if a bare `_vms[key] =` (any index form) or `AddOrUpdate`/`GetOrAdd`/`TryAdd`/`TryUpdate` appears outside the marked creates and `UpdateVm`. No product code changed.
