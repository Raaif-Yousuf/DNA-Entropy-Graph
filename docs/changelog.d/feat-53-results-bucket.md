- The results bucket is real in the code (issue #53): the app creates one private Cloud Storage bucket per Google project named `deg-<project number>-<6 letters>`, with uniform access, public access blocked, the app's labels, a rule that deletes job files after the retention you chose (90 days by default) and a rule that deletes the model cache after 365 days. It then reads the bucket back and refuses to report success unless every one of those settings is really there. A second computer on the same project finds the bucket by its label and uses it instead of making another; a changed retention is applied to it. A taken name is retried with a new suffix, five times at most. `app-config.json` is written at the bucket root. Uploading and downloading job files has a real implementation too. A bucket found on a later run gets its `app-config.json` if it never got one, two computers that both made a bucket end up on the older one (the newer, empty one is deleted), a changed retention keeps any lifecycle rules you added yourself, and a retention below 1 day or above 3650 is refused before anything is sent. Production still uses the offline stand-in until the Google layer is switched on (#56).
