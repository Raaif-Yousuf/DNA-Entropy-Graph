- feat(app): monthly spend ledger and spending cap (#109). When a run row ends (any writer: runner, reconciler, cleanup) a `vm_runtime` CostLedger row is written once per run, booked from the moment the runner knows its VM exists (`VmReadyAt`, now set by the runner) to the run's end at the machine's rate (Spot rate for Spot) plus its boot disk; a run with no VM books nothing. Migration 0003 adds a unique index on (RunId, Kind) and the repository inserts with INSERT OR IGNORE, so concurrent writers book a run once; the run row is stored before the ledger row. Month-to-date is summed over the local calendar month and adds the VM time accrued so far by runs still going ("includes runs in progress"). Settings > Spending adds a warning cap and a hard stop. The New run page shows a cap card (refreshed whenever the page is shown, also with no file chosen), and with the hard stop on it turns red and disables Run; the engine asks the same shared path (the run's own estimate plus month-to-date) and refuses before anything is created with the new `spend_cap` error (action: Open Settings). Not counted: a VM kept alive or stopped after its run ended, time before the VM existed, bucket storage. All figures are estimates; #557 and #150 can read the same ledger.
