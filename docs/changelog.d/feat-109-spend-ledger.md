- feat(app): monthly spend ledger and spending cap (#109). When a run row ends (any writer: runner, reconciler, cleanup) a `vm_runtime` CostLedger row is written once per run (migration 0003 adds a unique index on (RunId, Kind), duplicates removed first; the repository inserts with INSERT OR IGNORE; the run row is stored before the ledger row; the registered repository keeps the #113 phase guard). The booked span is one rule in one helper used by every path (runner create, reuse, adoption and resume, cancel, reconciler): it starts at the VM's own platform start from any observation of the VM and never at the app's clock; it ends at the VM's stop time if it stopped, at the last time the app knew a self-deleted VM was alive, or when the run ends if the VM is still running; a run that never observed a VM books nothing. A VM that stopped itself and is resumed hours later books the time it ran, not the time the app was closed; a cancel in a fresh process books the VM it finds. The rate is the machine's hourly rate (Spot rate for Spot) plus its boot disk; month-to-date is summed over the local calendar month and adds VM time accrued by runs still going ("includes runs in progress", capped at the run limit plus grace; a granted flex VM that is booting counts, a queued request does not). Settings > Spending adds a warning cap and a hard stop. The New run page shows a cap card (also with no file chosen; not for a This PC run), and with the hard stop on it turns red and disables Run; the engine asks the same shared path and refuses before anything is created with the new `spend_cap` error (action: Open Settings). Not counted: a VM kept alive or stopped after its run ended, time before the VM existed, bucket storage. All figures are estimates; #557 and #150 can read the same ledger. A gone VM with no sign of life books at most its run limit, and the cloud runner records the worker heartbeat on the run row (at most once a minute); a cancel deletes and books the VM a create answered by its own name even when the label listing lags, and a create that lands after the cancel stopped waiting is deleted when it lands.
