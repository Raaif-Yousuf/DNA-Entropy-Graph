- feat(app): the Results page header and each Runs row show the run's estimated cost: the figure the spend ledger booked for that run, and nothing else (#100, #557). The run's ledger entry is the only record of a run's cost: it is first-write-wins, so two writers, a later copy of the run, or a later finish time never change what a run shows, and the run pages always match the month total. Spot-aware wording (a Spot run on a machine with no Spot price reads as an ordinary estimate; the wording follows the current price list, a documented limit), "no cloud cost" for This PC runs, no line for a run that never had a VM, and no line when the ledger cannot be read. The Runs page shows a run's cost as soon as the run ends while the page is open, and stops listening once you have left it; the app resolves its UI dispatcher on the UI thread at launch. Nothing is written onto the run row; `RunRecord.ActualCostUsd` is documented as reserved and unused. Run targets are the shared `RunTargets` constants, compared case-insensitively. The support zip's cost field is the same ledger figure and its VM seconds are the booked span; reading a cost never writes: a run whose ledger write failed is booked once at the next launch (a repair at startup that runs on the thread pool, never on the UI thread, beside the launch reconcile; a failure is logged as run-cost-repair by error class only, a cancelled launch logs nothing), and the support zip's VM seconds are the span that same ledger entry froze at booking (clamped to the run's limit, never negative), null when nothing was booked, even if the run row changes later; a failed cost read is logged by error class. The support zip reads each run's cost and seconds together from one ledger read, so neither can appear without the other. Entries written by pre-release builds may show unclamped seconds. The run cost line's one key-by-variable string.Format site (RunCostText) is listed in the format-arity guard's known-dynamic allowlist.
