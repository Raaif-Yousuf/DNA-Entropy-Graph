- The results bucket is real in the code (issue #53): the app creates one private Cloud Storage bucket per Google project named `deg-<project number>-<6 letters>`, with uniform access, public access blocked, the app's labels, a rule that deletes job files after your retention (90 days by default) and a rule that deletes the model cache after 365 days. It reads the bucket back and refuses to report success unless every one of those settings is really there. A second computer on the same project finds the bucket by its label (across every page of the listing) and uses it instead of making another; two computers that both made one end up on the older one and the newer, empty one is deleted. A bucket found on a later run is repaired if its access settings or rules drifted, and gets its `app-config.json` if it never got one. A different retention on another computer can lengthen the job-files rule but never shorten it, because shortening would delete results other computers expect to keep (#597; an explicit, confirmed shortening is #598); rules you added yourself are kept. A taken name is retried with a new suffix, five times at most, and a retention below 1 day or above 3650 is refused before anything is sent. Uploading and downloading job files has a real implementation too (a failed upload is retried from the first byte). Production still uses the offline stand-in until the Google layer is switched on (#56).
