- app: the Results page (#102). A finished run on the run page has View results, and a finished run's Open on the Runs page now lands here instead of the viewer. The page shows a per-contig header (length, mean, lowest and highest entropy, direction) read from the run's own summary file (`stats.txt` or `<name>.summary.txt`, parsed by `Core/Runs/RunSummaryReader.cs`, never recomputed in C#), and one row per file in the run's output folder with Open, Show in folder and Copy path, plus Open folder and Open in viewer. A missing folder, a missing summary or an unreadable summary shows a message naming one action instead of blank fields. Open only opens the file types the worker writes (an allowlist of final extensions in `ShellOpenPolicy`; anything else is refused, Show in folder still works). A OneDrive online-only file is listed, a link leading outside the run folder is not. The reading direction is shown as plain words, not the worker's raw token. The summary layout is pinned by `tests/contract-fixtures/run_summary_two_contigs.txt`, which `worker/tests/test_run_summary_fixture.py` regenerates from the mock pipeline.
