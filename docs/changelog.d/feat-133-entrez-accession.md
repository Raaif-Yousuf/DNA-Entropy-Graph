- feat(worker): `dna-entropy run --accession NC_045512.2 [--accession-range 100-500] [--ncbi-api-key K]` fetches a GenBank record from NCBI E-utilities, caches it, and runs it as a normal GenBank input (genes kept, not re-annotated). The accession is pattern-checked before any request, an NCBI error body with HTTP 200 is refused and not cached, requests are rate limited (0.34 s, or 0.1 s with a key), and `provenance.json` records `input_source` with the accession, range and ORIGINAL retrieval date (never the API key). The suite fakes the network (#133). The app's "Fetch from NCBI" button is a follow-up.
- fix(worker): #133 cold review. The accession pattern is ASCII-only (Arabic-Indic digits and long s used to pass). The NCBI fetch has a 120 s total deadline and a 64 MiB cap while the body streams in. Rate limit (429), NCBI trouble (5xx), a rejected request (400, 404), a refused key (401, 403), a timeout and a too-large record each have their own message and one action; 429 and 5xx are retried once after a backoff. A body without its closing `//`, without a VERSION line, or for a different record is refused and never cached. The cache and `provenance.json` carry the RESOLVED versioned accession (and what was requested); an unversioned request always asks NCBI. `--accession` now checks every other option before the network call and refuses a conflicting `--informat`
