- Save diagnostics no longer refuses on a real profile (#626). MEASURED 2026-10-03: a run whose name was its own job id (and, by the same shape, a run's `jobs/<id>/` bucket prefix) put the job id on the scrub list while the run history copies it verbatim, so the final leak scan refused with rule `identifier` on `run-history.json` and no zip was written. A job id in the app's own shape is shipped and a name or prefix that is exactly it is exempt from the scrub list; a job id in any other shape (the owner's real run has one) is never shipped and becomes `withheldid<n>` in the history and in entry names, and every occurrence in a file body (a `jobId` leaf, a log line) is rewritten to the same placeholder even when the scrub list would drop it (an all-digit record number); the `jobId` leaf of a run folder always ships the folder's own id. The standard-id pattern is now ASCII-only and anchored with `\A` and `\z`. Every other name, path and identifier is still scrubbed and checked. A refusal now carries the check that fired (`DiagnosticsLeakException.Rule`, `LeakRules`) and Settings traces that fixed word, never user text. `docs/threat_model.md` section 5b updated.
