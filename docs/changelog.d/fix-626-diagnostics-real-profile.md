- Save diagnostics no longer refuses on a real profile (#626). MEASURED 2026-10-03: a run whose name was its own job id (and, by the same shape, a run's `jobs/<id>/` bucket prefix) put the job id on the scrub list while the run history copies it verbatim, so the final leak scan refused with rule `identifier` on `run-history.json` and no zip was written. A job id in the app's own shape is shipped and a name or prefix that is exactly it is exempt from the scrub list; a job id in any other shape (the owner's real run has one) is never shipped and becomes `withheldid<n>` in the history and in entry names, while it stays scrubbed from file text. Every other name, path and identifier is still scrubbed and checked. A refusal now carries the check that fired (`DiagnosticsLeakException.Rule`, `LeakRules`) and Settings traces that fixed word, never user text. `docs/threat_model.md` section 5b updated.
