- Feature (#177): the run page line under the progress bar now explains the waits from the worker's own report, not the run history. The worker writes `detail.cache` (`hit`, `miss`, `saving` or `unavailable`) at the model-cache step: `hit` before the restore starts (so it shows for the whole restore), `saving` while the downloaded model is copied to your cloud storage. On a miss (nothing saved in your cloud storage and nothing on the rented computer either; a computer that already holds the model shows the plain loading line) the page says the model is not saved in your cloud storage yet and is being downloaded, which takes several minutes (no minute count, no "first run" claim), then that a copy is being saved so later runs can usually start faster; when the saved copy could not be checked or used it says so and that the model is being downloaded instead; on a hit it says the saved model is being reused, through the restore and the load; during `installing` it says the rented computer is getting the analysis software ready (no timing or frequency claim); and a This PC run never mentions a cloud cache. Text lives in `Resources.resw`; the page stays at two live regions.
