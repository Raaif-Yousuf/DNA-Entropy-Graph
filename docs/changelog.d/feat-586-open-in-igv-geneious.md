- app: the Results page has Open in IGV and Open in Geneious (#586, stacked on #102). Open in IGV connects to IGV's batch port (default 60151, key `Viewer.IgvPort`, read but not yet settable: the Settings page #104 will write it) on loopback and sends `new`, `genome` (the run's .fasta), `load` for each .bedgraph, then `load` for each gene .gff3 (the Geneious-only `.geneious.gff3` is left out), one command at a time, reading IGV's one-line `OK` before the next (20 s wait for `new`, 60 s for `genome` and `load`, since a big track loads as slowly as a genome and a retry would resend it; leaving the page cancels a wait in progress). Only a refused connection means IGV is not running and starts it with `-g <fasta>` and the tracks (no shell, one argument each). MEASURED 2026-10-03: a refused loopback connect takes about 2.07 s on Windows, so the connect wait is 6 s; a connect that times out or fails otherwise (IGV busy) is reported ("IGV did not answer") and never answered with a second IGV, and a rejected command or a missing reply is reported the same way. Paths are double-quoted; a path with a quote or line break gets its own message naming the action. IGV holds one genome, so a run with several inputs opens the first and says so, and a run with no .fasta says so instead of loading tracks onto an unrelated genome (the message names only Open folder, because no screen selects output files yet). A `.bat` or `.cmd` program (the Browse filter allows it, and `igv.bat` is a locator fallback) is run by cmd.exe, so a launch whose file path holds one of `& | ^ % < > ( ) !` or a quote is refused with a message naming the action (an .exe is unaffected). Open in Geneious starts Geneious with the run's .gb then .gff3 files. The program is the saved path (`Viewer.IgvPath`, `Viewer.GeneiousPath`), else autodetected under Program Files and the per-user Programs folder (`ViewerLocator`; install folders `IGV-<version>` or `IGV_<version>`, newest by number, so 2.19.7 beats 2.9.4), else the user's Browse choice, which is saved; a program that will not start is forgotten so the next press asks again. Files are chosen from the run's output listing by the worker's writer names (`Core/Viewers/ExternalViewerFiles.cs`); an absent file is skipped. Every failure is one message naming one action (`Results_Igv*`, `Results_Viewer*` and `Results_Geneious*` in `Resources.resw`). Sockets and process launch sit behind `IIgvBatchClient` and `IViewerProcessLauncher`. No paths are logged. Unproven on a real IGV or Geneious: see `docs/ToTest.md`.
