- ci-app and ci-worker no longer use a workflow-level `paths:` filter (#31): they always start on a pull request and a `changes` job skips the real jobs when nothing under `app/` or `worker/` changed, so an empty PR shows every check as passed or Skipped instead of a required check that never appears. The check names and the empty-PR expectation are in `docs/tests.md`; requiring them on `main` is an owner action.
- The ci-app and ci-worker `changes` gates now list every path their tests read (worker/, tests/, docs/contract/, docs/copy_catalog.md), so a PR editing only a file a test reads no longer shows the tests as Skipped (passing); scripts/tests/test_ci_gate_sync.py keeps the lists honest (#31).
