- Delete cloud copy on the Runs page now really deletes that run's files (#262, #534): only that run's own folder in your Google Cloud storage, never the saved model files or other runs. It reads the folder back afterwards, so a partial delete is reported and finished by pressing the button again, and every message says only what the app knows. Files known to remain are counted ("Files still in your Google Cloud storage: N"), and when the cause is a refused permission, an organization rule, billing, a switched-off service or Google's request limit the message names that cause's one action together with the count. When the app could not count what is left it says files may remain, never that they do, under a "may be partly deleted" title with the action for the cause, or says the delete finished but could not be confirmed empty when only the check failed. A connection cut mid-delete (a reset, a dropped socket) is treated as a dropped connection, so the page names the internet check, and a storage listing that repeats a page token (`LIST_PAGINATION_STUCK`) is told as a plain failure, not as a network drop: the Google gateways keep their own classification (so the reconciler still reads it as no answer) and only the delete copy chooses by that code. The real-GCS check of the delete is in `docs/ToTest.md`.
