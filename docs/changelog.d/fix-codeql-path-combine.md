- Hardened two path joins fed by history-database text: a stored `portable:` path with a rooted or climbing remainder is no longer expanded outside the portable folder (DataPathMapper), and a job id that is rooted or climbs no longer reads a log outside the runs folder (FileLogTailReader). The remaining CodeQL path-combine alerts in product code were triaged as safe (constant segments, validated ids, already-contained result paths).
- A poisoned portable output folder in the history database now reads back as no output folder instead of an unexpanded path, and the shared containment test (RunOutputRoot) now works for a drive-root folder such as D:\.
- A history row that names an output folder outside the run's output root can no longer make a finished local run copy files there on relaunch, and a drive or share root as the output folder no longer makes folders below it deletable or re-downloadable from History. A job id such as x\..\y no longer shows another job's log.
- A resumed cloud run no longer reuses a recorded output folder that lies outside the output folder chosen for it (it makes a fresh one), a local job id must be one plain folder name, and the poisoned-row log line is written once per run. A network share as the output folder keeps working for delete and re-download.
