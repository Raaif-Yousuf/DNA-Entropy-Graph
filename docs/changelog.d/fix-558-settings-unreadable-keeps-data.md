- fix(app): an unreadable or hand-edited `settings.json` no longer wipes every setting and the installation id (#558). `SettingsStore` now holds the file as JSON of any value type: numbers, bools, null, objects and arrays no longer make the file "unreadable", and a `SetString` rewrites every other key with its original JSON value and type (no coercion on rewrite; `GetString` reads a number as its invariant text, e.g. `1`). A file that truly does not parse is copied to `settings.json.unreadable-<yyyyMMdd-HHmmss>` before any write (the write is refused if the copy fails), scalar pairs are salvaged from it so `installation_id` survives and no new id is minted (Hard Rules 9 and 10), and `RecoveredFromUnreadableFile` is exposed for the recovery UX that waits on DECISION #404 (no UI or copy added here). A file that cannot be read (locked) makes writes throw instead of replacing it. Writes were already temp file plus `File.Move(overwrite)` and still are. DECISION #565 (agent-made, reversible): keep the id in settings.json and salvage it, not a separate id file.
