- fix(app): an unreadable, locked or hand-edited `settings.json` can no longer wipe settings or change the installation id (#558). The installation id now lives in its own write-once file `installation_id` beside settings.json (created with CreateNew and flushed; a legacy id in settings.json is migrated once; two first-run processes converge on one id; an invalid id file is kept aside and surfaced, never replaced, so no new id is minted and labelled cloud resources (Hard Rules 9 and 10) stay visible). `SettingsStore` reads settings.json as JSON of any value type (numbers, bools, null, objects, arrays), rewrites every other key with its original type on `SetString`, and for a file that does not parse keeps a `settings.json.unreadable-<yyyyMMdd-HHmmss>` copy before any write and salvages completed depth-1 scalar pairs with `Utf8JsonReader` (nested values skipped, types kept). `RecoveredFromUnreadableFile` is set only for that corruption and is sticky for the instance (recovery UX waits on DECISION #404; no UI or copy here). Every IO, ACL or lock failure in the store (temp file, folder, keep-aside copy, mutex, move) becomes `SettingsUnavailableException` with the cause kept, after a total wait of about 300 ms per call (the callers are on the UI thread); window placement (best effort on close), theme (which now shows a failure message instead of "theme updated"), Settings, New Run and the worker-image lookup catch it and carry on, and a run start fails before any cloud resource exists with the `other` code. A corrupt settings.json that still holds the id after the corruption point has it recovered by a lenient scan; if the id is mentioned but unrecoverable, no new id is minted and the run fails with the new `installation_id_unusable` code. The id file is published by a flushed temp file moved into place (never torn), and a whitespace-only or BOM-only id file counts as absent and is replaced. Writes are a flushed temp file then replace, under a named cross-process mutex so two instances never drop each other's keys. DECISION #565 (agent-made, reversible) now records the own-file design, reversing its first salvage-only answer.
