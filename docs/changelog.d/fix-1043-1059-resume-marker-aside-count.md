- A resumed cloud run now writes into the folder its history row names only when that folder carries the run's own marker (`.dna-entropy-run` with the job id); otherwise it makes a fresh marked folder under the output folder and the named folder is left untouched (#1043). Runs from before markers existed download again into a fresh folder. The reconciler's output-root fallback follows the same rule. The count of changed files kept under a new name is now saved on the run row at the moment of each rename, so a cancel, a cloud error such as a 403, or a resume after the app closed mid-download still shows it on the Runs row (#1059).
- A resume that has to switch to a fresh output folder now resets the row's kept-under-a-new-name count to 0 in the same update, because the earlier folder's renamed files are not in the new one (#1059).
