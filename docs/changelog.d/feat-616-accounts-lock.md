The first such change afterwards fails once with the new code `ACCOUNTS_FILE_UNREADABLE` (message in `Resources.resw`, `copy_catalog.md` and the triage roster, action Sign in again) before a browser opens. A missing file is still a normal empty list. The file is read under the same lock with a short bounded retry; one that exists but still cannot be read (held open elsewhere) is never replaced, is not cached as empty, and fails the change with the new code `ACCOUNTS_FILE_LOCKED` (action Try again) until a later call can read it. While locked a read is not retried more often than every 2 s, and a token request or sign-out fails with the same code instead of reading as signed out or expired A save that cannot take the lock (timeout, or the system refusing the mutex) fails sign-in, switch and project choice with `ACCOUNTS_FILE_LOCKED` instead of a disk-space message; saves run off the caller's thread, a load blocks at most about 270 ms, a damaged file that cannot be set aside reports `SIGNIN_STORAGE`, and stale `accounts.json.*.tmp` leftovers are removed on save (#616)
