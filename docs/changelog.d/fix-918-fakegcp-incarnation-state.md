- FakeGcp (the test double for every cloud interface) keeps all per-VM state (label fingerprint, max run duration, boot and stopping poll countdowns) by VM incarnation (InstanceId) instead of by name, so a VM deleted and re-created under the same name inherits or loses nothing of the old one's. Boot and stopping polls only finish the incarnation they read; an internal (worker) stop is per call, not a shared flag; a create's exists check and insert are one atomic step; the quota and already-exists tables are concurrent; a worker undo restores a key only while it is still what the worker wrote, and a throw between the worker's return and the start or grant is undone. The _vms guard now rejects every mention of the dictionary that is not a read, a removal, a foreach, the marked create or the helpers' own swap (aliases, casts, ref, Clear). (#918)
- FakeGcp, follow-up (#918 cold review): a delete settles the removed VM's disks and deleted-signal before its plan cleanup so a VM made again in that gap keeps its own; a queued flex request's server task is bound to its own incarnation; the already-exists mark belongs to the VM it marked and goes with it (also when a setup displaces a live row); each simulated live worker is its own value so an undo never takes another create's worker; a create writes its per-incarnation state before its row lands. The `_vms` guard also rejects `this._vms` aliases, `??=`, `in _vms` arguments and a `TryAdd` outside its expression-bodied helper. (#918)
