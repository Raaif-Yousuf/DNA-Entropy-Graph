- Result downloads stream from the bucket straight to a temporary file instead of buffering the whole object in memory (#588): a probability matrix of hundreds of MB no longer needs that much RAM. The finished file is still checked against the size and SHA-256 the worker reported before it takes its final name, and a failed or cancelled download leaves no partial file behind. A download that goes silent is cancelled after 90 seconds without data (a slow connection that keeps moving is never cut), each attempt uses its own temporary file, and a resumed run keeps a file you edited under a (changed ...) name instead of overwriting it, putting it back if the new file cannot be moved in, and telling you to open the output folder when it did. Only the app's own temporary files older than a day are cleaned up, never another .part file of yours, and never through a shortcut folder.
