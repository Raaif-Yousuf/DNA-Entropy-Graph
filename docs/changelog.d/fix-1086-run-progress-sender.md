- Fix (#1086): the run page's progress bar and detail line now move. `RunProgressChangedMessage` had a receiver and no sender; the cloud runner (`OnProgress`, from the polled `status.json`, reattached runs included) and the This PC runner now publish each new progress event once, through `WorkerProgressTracker`. The worker now writes `percent` (whole job, equal share per input) and `detail.window`/`windows` per window (throttled to one status write per 2 s), so the bar and the "part N of M" line have real data; the page text comes from `Resources.resw` (a stage the page does not know shows a neutral line, never the raw stage id or a file name) and an event after the run ended is ignored. New guard `MessageHasSenderGuardTests` fails when a messenger message has a receiver (a `Register<...>` call or an `IRecipient<...>` implementation, comments ignored) and no sender. A run page opened or shown again mid-run now starts from the run's last progress (`RunProgressStore`) instead of staying blank until the worker's next change; the unused "saving your results" line (no worker stage `uploading` exists) is gone. The store forgets a finished run and drops a progress event that arrives after it (progress and phase are published from different threads), so a finished run opened from History no longer shows a stale bar; a test through the real container proves the page receives the store.
