- Setting up a Google Cloud project is real in the code (issue #50): the app lists the active projects an account can see (the ones it made first), makes a new `dna-entropy-<random>` project with one click, waits up to 5 minutes for Google to finish, and reports the project limit (PROJECT_QUOTA, action Pick an existing project) and an organization block (ORG_POLICY_BLOCK, action Copy message for IT) by name. A refused create names the button that fits (ask the project owner, turn a service on, or link billing) instead of Try again. The wizard page that calls it arrives with #99, and production still uses the fake cloud until #56, so nothing in the shipped UI changes yet. The real Google calls use the REST client package Google.Apis.CloudResourceManager.v3 (Apache-2.0); Google.Apis.Auth moved to 1.77.0 with it.
- The project calls never make two projects from one click (issue #50): the create is retried alone after a dropped connection, a project that already exists is adopted only when it is one of ours, a hiccup while waiting is a re-read and never a second create, a per-minute rate limit is retried instead of being reported as the project limit, a spent wait ends at its 5 minute limit even when one check hangs, a finished create with no project in its answer is looked up instead of reported as a success with a blank id, and looking up an id that is not a legal Google project id answers "not found" without asking Google.
