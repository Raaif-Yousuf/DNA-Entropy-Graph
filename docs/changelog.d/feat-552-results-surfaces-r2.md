- app: Results page and viewer surfaces for the worker's new outputs (#552). Results lists every `<name>.genes.tsv` as a table you sort by clicking a heading (first click lowest first, again to reverse; numbers sort as numbers, ties keep the file's order; the first 500 rows are drawn and a note says "500 of N genes shown, sorted by X" and names the file for the rest; gene names sort naturally, g2 before g10, the same on every language setting). The file is read by column name by `Core/Tracks/GeneTable.cs` from the run folder and the one level of per-input folders below it: an added or reordered column still reads, a row that cannot be read is left out and counted in a message, and every unreadable table is counted and named with Open in the file list as the action. A smoothed track the page cannot load turns its tick box back off with a message to tick it again (`trackFailed` event from `bridge.js`). The embedded viewer draws `<name>.regions.bed` (else `.regions.gff3`) as an "Entropy regions" feature track, and lists each `<name>.entropy.smooth<W>.bedgraph` as a tick box (off at first so the raw track stays primary) that adds or removes a 0 to 2 bit track through a new `track` command in `bridge.js`. `RunOptions` gains `RegionThreshold`, `RegionMinLength`, `RegionMergeGap` and `SmoothingWindows`, which `WorkerManifestBuilder` sends as `analysis.regionThreshold`, `regionMinLength`, `regionMergeGap` and `smoothingWindows` only when `regions` or `smoothed` is chosen (no settings screen for them yet). The probability matrix switch already existed (off by default, #103). Unproven on a real build: see `docs/ToTest.md`.
